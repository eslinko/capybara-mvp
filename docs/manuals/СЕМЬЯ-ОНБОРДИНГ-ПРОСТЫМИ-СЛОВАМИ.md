## Словарь: что значит «тех-жаргон»

| Слово в доках | Простыми словами |
|---------------|------------------|
| **Host / хост** | Наш сервер Capybara в интернете (ссылка выше). |
| **Connector** | Отдельная страница, где MetaMask просит «подписать» сообщение. Это основной способ войти, не старый `/sign/*`. |
| **MetaMask** | Кошелёк в браузере/телефоне. Им ты подтверждаешь, что адрес — твой. |
| **Адрес / address / 0x…** | Публичный номер кошелька (как номер счёта). **Не** секретный ключ. |
| **Sign / подпись** | MetaMask показывает текст → ты жмёшь «подписать» → сервер убеждается, что ключ у тебя. |
| **AddressProof («доказательство адреса»)** | Короткий результат успешной подписи: «этот 0x… только что подтвердил владение». Нужен для bootstrap и приглашений. |
| **Auth user** | Учётная запись в Supabase Auth (часто email вида `0x…@capybara.local`). Появляется после подписи+verify. |
| **Bearer / токен** | Временный «пропуск» после входа. После перезапуска сервера может пропасть — это нормально. |
| **Bootstrap** | Один запрос «создать семью»: основатель + пул. **Без** bootstrap подпись даёт только Auth-пользователя, **не** роль родителя в семье. |
| **Family / семья** | Наша запись семьи в базе (есть `familyId`). |
| **Membership / членство** | Кто ты в семье: `parent` (родитель) или `child` (ребёнок). |
| **Invite / приглашение** | Родитель говорит серверу: «этот адрес — ребёнок/сородитель». Без секретной ссылки-токена: вход по адресу кошелька. |
| **Pool / пул** | Адрес «кошелька семьи» (из настроек `CAPY_POOL_ADDRESS`). Задаётся **на bootstrap**, отдельной кнопки «создать пул потом» нет. |
| **Postgres / durable** | Постоянная база: семьи, членства, приглашения, доказательства. Переживает перезапуск Railway. |
| **Soft Present** | В коде и на сервере фича есть. |
| **Live Pass** | Мы **записали** живое прохождение сценария. Пока не записали — не говорим «онбординг Done». |
| **Residual** | «Ещё не доказали в живую» — честный статус, не провал продукта. |
| **Soft ≠ Live** | «Код есть» ≠ «мы уже прошли весь сценарий на проде и поставили галочку Done». |

## Шаг 1 — Основатель: две подписи → один bootstrap

**Идея:** подпись сама по себе **не** делает тебя основателем семьи. Нужен **один** вызов bootstrap с **двумя** доказательствами: родителя и пула.

1. Открой Connector:  
   https://capybara-mvp.up.railway.app/connector/launch?mode=platform-auth&platform=capybara  
   (или напрямую https://dogestonia-connector.up.railway.app/?mode=platform-auth&platform=capybara)
2. Подпишись кошельком **родителя** → сохрани AddressProof / сессию.  
3. Подпишись кошельком **пула** (`CAPY_POOL_ADDRESS`; если адрес тот же — можно тем же кошельком ещё раз по сценарию продукта).  
4. Один раз вызови bootstrap на хосте:

```bash
BASE=https://capybara-mvp.up.railway.app

curl -sS -X POST "$BASE/auth/bootstrap" \
  -H 'Content-Type: application/json' \
  -d '{
    "poolProof": { "address":"…", "challengeId":"…", "verifiedAt":"…", "verifiedAtMs":0 },
    "parentProof": { "address":"…", "challengeId":"…", "verifiedAt":"…", "verifiedAtMs":0 }
  }'
```

Подставь поля из ответов verify (см. EN [`IDENTITY-HTTP-EDGE-MANUAL.md`](IDENTITY-HTTP-EDGE-MANUAL.md) §3.2).

**Ожидание:** в ответе есть `familyId`, `founderRole: parent`, `bootstrapped: true`. В базе появляются семья и членство родителя.

**Нельзя:** делать «bootstrap только для родителя» или «сначала семья, пул потом отдельным API».

## Шаг 2 — Пригласить Tristan и Bastian

Родитель уже вошёл (есть Bearer). Для каждого ребёнка — запрос приглашения:

```bash
BASE=https://capybara-mvp.up.railway.app
TOKEN='…'   # Bearer после входа родителя
FAMILY_ID='…'

curl -sS -X POST "$BASE/auth/invite" \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"to\":\"$TRISTAN_ADDRESS\",\"role\":\"child\",\"familyId\":\"$FAMILY_ID\"}"

curl -sS -X POST "$BASE/auth/invite" \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"to\":\"$BASTIAN_ADDRESS\",\"role\":\"child\",\"familyId\":\"$FAMILY_ID\"}"
```

Адреса детей должны быть известны **до** приглашения. Отдельной «секретной ссылки-приглашения» нет — вход идёт по адресу кошелька.

## Честный итог (что можно и нельзя говорить)

| Можно сказать | Нельзя сказать без Live Pass |
|---------------|------------------------------|
| Сервер отвечает на `/health` | «Онбординг семьи полностью Done» |
| Код Soft Present (приглашения, Postgres, Connector) | «REQ-12 / Phase 3 Accepted» только из этого гайда |
| Чистый Auth на `0xbd9a…` сделан `2026-11-27` | «Live MetaMask cast Pass», если evidence нет |

**Честность после bootstrap:** ответ `ok: true` без строки в таблице `families` в нашем Supabase = запись ушла не туда (память процесса / старый деплой), а не «всё хорошо». То же для invite → `invites`, вход ребёнка → `memberships`. Подпись «только адрес» без успешного verify в базе для bootstrap — **не** безопасно (гап AUTH-07).

**PGDUR-06 Soft≠Live:** в логе старта хоста смотри `store_kind=postgres` (иначе FailClosed / inject). Живой cast Pass пока **Residual OK** (PGDUR-05 / EDGE-08) — Soft-тесты ≠ Live Pass / REQ-12 Done. Адреса `CAPY_POOL`/`PARENT` сами по себе не «включают» прочность базы.

Когда пройдёте шаги 1–4 вживую — запишите UTC, `familyId`, роли и ссылку на evidence в `docs/manuals/evidence/`. До записи — статус Residual, не Done.
